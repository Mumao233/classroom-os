**结论：未达到“无 P0/P1”的复审门槛。** 以下是 r2 的问题清单（已于 `8cd9033` 修复，保留作历史记录）：

- P1 提交前读绑定课堂的成员关系用了缓存（`ensureQueryData`），其他设备移动课堂后会误判；应强制新读。
- P1 不确定删除的临时清扫中，`cancel({ revert: true })` 同步触发缓存订阅，`learn()` 看到临时级联而写入永久撤销并调用撤销钩子（第 1 轮修复引入）。
- P1 不确定删除恢复账本后 `isEmpty()` 早于 `droppedQueries` 检查，晚到的 mutation 回复可重新填回被丢弃的资料（第 1 轮修复引入）。
- P1 学期级联后晚到的课程列表里属于该学期的课程未记入账本，随后到达的课堂只被“暂停”而非确认撤销。
- P1 删除请求自身返回 401 时没有走账号纪元退出（只有查询 401 会）。
- P1 版本读取被拒绝后，已打开的个人稿编辑框里仍显示从该版本复制的服务端正文。
- P2 演示课堂先 404 后登记成功，旧拒绝标记未清除，之后离线时被隐藏。
- P2 已确认撤销的课堂，首次离线打开其详情只显示“无法连接”，不显示“已删除”。
- P2 暂停采集的停止在计算摘要期间若课堂被确认撤销，续写的待确认停止会复活。
- P2 只读回退中“重新准备”重新转写按钮未检查 `online`（10b 既有，r5 P3 同类）。

合并后复审遗留问题（判定成立；6 个 P1 已在第 4 节修复，P2 未处理）：

- P1 非绑定课堂的缓存父级链接仍被当作级联证据；其他设备移动后会误撤销或漏撤销。
- P1 不确定删除取消进行中读取时 `revert` 恢复到刷新前快照，可能带回已撤销的行，且临时清扫期间守卫被暂停。
- P1 确认清扫中 `setState` 同步触发订阅，`learn()` 从清扫的中间结果学到永久撤销（同 revision 冲突被部分清除后）。
- P1 版本读取被拒绝后再次进入阅读页，重读进行中 `revisionsDenied` 为假，编辑框可显示并提交复制来的正文。
- P1 资料/版本已加载但课堂详情与列表从未加载时，课堂的首次 `NOT_FOUND` 不被采信，资料仍可显示。
- P1 同一数据集内切换 Mock 场景会清掉运行时的已删课堂，账本仍认为已撤销但不再触发停止钩子。
- P2 学期级联时课堂列表先于课程列表到达，课堂无法被确认撤销（只测了相反顺序）。
- P2 `move_children` 后离线时，缓存的子项仍指向被删父级（仪表盘、课堂记录显示不对）。
- P2 回执只校验 scope 与 state 字符串化，未按 `Deletion` schema 校验。
- P2 `droppedQueries` 按 Query 实例弱引用，查询被回收后晚到的 mutation 回复可重新填入。
- P2 暂停采集的停止应在摘要计算后、发送前检查撤销，而不是请求结束后。
- P2 验收记录未区分第 3 轮修复与最后验证的快照（本次更新已处理）。

- P1 列出的成员关系没有绑定删除事务（列出后、删除前的移动）。契约（`04-CONTRACTS-FLOWS` 删除一行）要求确认 token 绑定对象版本/影响范围，Mock 只校验了版本；改为 Mock 预览时记下影响范围（课程与课堂 ID），删除时范围变了就返回 `PLAN_EXPIRED`，前端按明确拒绝处理（什么都不改，重新预览）。
