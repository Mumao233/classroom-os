# PR-11b 运营后台（前端）范围与缺口

日期：2026-11-23，2026-11-26 适配 HTTP 0.4.0（合入 main `bed9337`）。分支 `feature/web-pr11b-admin`。本 PR 不修改契约。

按 [08-IMPLEMENTATION](../../docs/web-alpha/architecture/08-IMPLEMENTATION.md)，11b 的后台 API 由 Codex 实现，界面由 Claude 实现。本 PR 只做界面，配合开发用的 Mock 后端（MSW），不接真实服务，也不调用任何真实模型或供应商。

## 需求

| 需求 | 本 PR 的界面落点 |
|---|---|
| AUTH-07 后台四页 | `/admin/users`、`/admin/invites`、`/admin/usage`、`/admin/runtime`（02-FRONTEND-AURORA §路由） |
| AUTH-07 管理操作 MFA 与审计 | 每个管理写操作都要填理由（1–500 字），并先做一次再认证（密码 + 验证码）；运行状态页列出审计记录 |
| AUTH-07 日志无正文/密码/Key/恢复码 | 界面不记录、不缓存密码、验证码、再认证凭证和邀请令牌；邀请令牌只在创建或重签的响应里显示一次 |
| AUTH-05 Admin 无默认正文、无冒充 | 后台只用 `/admin/*` 的无正文投影；没有“查看学习内容”“以该用户身份登录”之类入口 |
| FE-13 学生直接打开后台 URL | 界面先读 `/me` 的角色，学生不发出任何 `/admin/*` 请求；服务端同样以 `FORBIDDEN` 拒绝 |

## 页面

- **用户**：用户列表（邮箱、昵称、角色、状态、MFA、创建时间）。可停用或恢复账号（CAS `base_revision`），可查看某用户的额度桶，并追加额度（`/admin/quota-adjustments`）。
- **邀请**：邀请列表；创建邮箱绑定邀请或单次邀请；撤销、重新签发。一次性令牌只保存在组件内存里。
- **用量**：按月查看平台预算、已结算、预留、unknown、安全预留和价格版本。金额用整数微元字符串换算，不经过浮点数。风险占比对照 60%、80%、100% 阈值显示。
- **运行状态**：数据库、对象存储、worker 心跳、排队、unknown 任务、待删除和删除失败、ASR 流、最近备份；平台开关（六个分项，CAS + 理由 + 再认证；新采集和活跃用户阶段只读）；审计记录。

## 契约（HTTP 0.4.0）

最初按 0.3.0 实现时发现的缺口，已由 PR #40（HTTP 0.4.0，裁决 `docs/web-alpha/coordination/PR11B-CONTRACT-DECISION-20261124.md`）处理，本分支已合入并适配：

1. **管理写操作的再认证**（原缺口 1，已解决）。界面先 `POST /auth/reauth`，用途为六个管理员用途之一：额度、开关、新建邀请以当前管理员账号为目标；更新用户以路径中的用户为目标；撤销、重签以邀请为目标。凭证绑定未来写入的幂等键和完整请求体，只保存在写入意图的内存里。Mock 用同一个 HTTP 端口回答（只提供管理员用途），不再有进程内替身。
   - 后端目前只实现了额度和开关两项写入；用户更新和三项邀请写入签发凭证时返回 `503 SERVICE_DISABLED`（裁决 §1）。界面按操作提示“这项管理操作的服务端尚未开放”，验证码不会被消耗。Mock 实现了全部六项，便于演示和测试。
2. **邀请理由**（原缺口 7，已解决）。创建、撤销、重签都必须填写理由；`email_bound` 必须有邮箱，`single_use` 不得有邮箱。
3. **用量口径**（原缺口 8，已确认）。`fixed_and_accrued_microyuan` 只含周期固定占位；风险合计 = 固定占位 + 已知结算 + 剩余预留 + unknown 余量，与界面原有算法一致。
4. **平台开关**（0.4.0 新增）。开关页显示六个配置：收费总闸、开放邀请注册、实时转写、重新转写、AI 问答与讲解、AI 总结与卡片；“新采集”和“活跃用户阶段”只读（服务端暂不接受修改）。界面只编辑分项，不与同组汇总项混写。
5. **理由格式**。理由遵循 `AdminWriteReason`：1–500 个码点，至少一个非空白字符（显式的空白集合，含 U+0085、U+FEFF），不含 U+0000；界面在输入验证码前检查。

### 仍未在契约中规定的点

- **邀请创建或重签的响应丢失。** `x-replay-policy` 为 `non-secret-status`；Mock 按秘密签发规则返回 `409 SECRET_ALREADY_ISSUED`，界面提示刷新列表后“重新签发”。
- **能否停用自己或其他管理员。** 界面不给自己的账号显示停用按钮；Mock 拒绝停用自己（`FORBIDDEN`）。
- **审计记录只有 `actor_id`。** 界面用用户列表换成邮箱；用户列表不可用时显示记录里的 ID。
- **管理员会话时长。** 由服务端执行（空闲 15 分钟、绝对 8 小时），界面统一按 `UNAUTHENTICATED` 退出。
- **用量只有平台汇总。** 按用户的明细通过 `/admin/users/{id}/quota` 查看额度桶。

## 其他说明

- 手机底部导航固定四项，管理员在手机上从“设置”导航末尾的“运营后台”进入；桌面导航对管理员多一个“运营”入口。
- 设置页“导入导出”和“删除与隐私”两个占位写着“计划于 PR-11b”，但它们不属于运营后台（导入导出是 08c，账号删除的后端在 04b）。本 PR 不改这两处文案，留给相应 PR 处理。
- Mock 增加了合成管理员账号 C（`admin@example.invalid`，已启用 MFA，没有学习数据）。开发面板“运营后台（PR-11b）”可以登录管理员、切换健康读数、切换管理员是否启用 MFA。Mock 的 `/auth/reauth` 接受任意非空密码和任意 6 位验证码，`000000` 表示验证码错误。
- 停用账号后，该账号在 Mock 中的所有请求立即返回 `UNAUTHENTICATED`，账号壳随之退出。

## 不在范围内

- 后台 API、权限、审计落库、独立限流（Codex）。
- 首个管理员创建、管理员 MFA 丢失恢复（运维工具，没有网页入口）。
- 搜索、通知、反馈（11c）。
