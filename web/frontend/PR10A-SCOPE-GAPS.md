## 3. 契约缺口与歧义（不改 openapi.json，必要时交 Astra）

1. **AI 解释结果没有读取接口。** `GenerationPlanRequest.kind` 有 `ai_explanation`，执行返回 `Task`，但 0.2.1 中没有解释结果资源（`Task.result_id` 指向的类型未定义）。本 PR 解释栏只显示计划确认与任务状态，不虚构结果字段。
2. **07a 问答候选契约未并入正式契约。** `docs/web-alpha/pr07a/CONTRACT.md` 的 `pr07a-1` 为 `Question` 增加必填 `cited_source_ids`、为 `SourceSnapshot` 增加 `items`，正式 0.2.1 没有。前端按 0.2.1 渲染问答，引用别名留待契约合并。
3. **课堂实时事件订阅入口。** 事件 schema 定义了 `transcript.partial/final`，但 OpenAPI 中没有 WebSocket 连接路径或订阅参数。Mock 使用内存 EventClient；真实接线需 Astra/Codex 确认连接方式。
4. **处理页的上传积压。** `AudioManifest` 只描述服务端已知范围；浏览器本地尚未上传的分片数量只能来自本机采集 runtime。处理页分别标注“服务端记录”和“本机记录”，不合并。
5. **试音。** 契约没有试音接口；试音完全在本机进行（Mock 中为模拟电平），不创建课堂、不上传、不计费。
6. **课堂创建与采集授权版本号。** `CaptureAcquire` 需要 `microphone/recovery/asr_consent_version`，契约未规定版本值来源（`Meta` 中没有）。Mock 使用固定合成版本字符串并在页面展示授权文字。
7. **错误细分依赖 `error.message` 文字（待 Astra 定夺，10b 开工前处理）。** 06c 交接要求前端用 `error.message` 区分 `GONE`（原音过期/已删除）以及 `QUOTA_EXCEEDED` 的课次额度与月额度两种情况；后端 `failure()` 已改为返回 `public_message`。把面向用户的提示文字当判断条件很脆弱（文案调整或本地化即失效），应由契约提供机器可读的细分字段或独立错误码。本 PR 只记录不处理；10a 代码只按 `error.code` 分支，不读取 `error.message` 做判断。
