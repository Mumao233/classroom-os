# 账号壳“收到删除回执即撤销”机制（设计说明）

适用范围：`web/frontend/` 的 Mock 工作台账号壳，覆盖 PR-09b（课程、仪表盘）、PR-10a（课堂、课后页）和 PR-10b（复习）。不改契约（OpenAPI 0.3.0 / 事件 schema），只用合成数据。

## 问题

PR-10b 前几轮复审反复出现同一类 P1：删除或撤权之后，页面仍从 TanStack Query 缓存里显示被删内容，或绑定在被删课堂上的采集继续运行。原因是撤销依赖“失效后重新读取”：

- 离线或刚断网时重读失败，TanStack Query 保留旧 `data`，页面继续显示；
- 级联删除只在课堂详情重读返回 `NOT_FOUND`/`GONE`/`FORBIDDEN` 时才撤销采集；
- 10b 加的 `evictClassroomFromReview`/`evictScopeFromReview` 只能找出缓存里已知成员关系的课堂，未知的课堂被当成不受影响；
- 删除对话框在请求进行中仍可切换“级联/移走”，`onSuccess` 读到的是新选项。

## 设计

一个账号纪元一个 **撤销账本**（`src/features/revocation.ts` 的 `createRevocationLedger`），由账号壳创建并通过 `AppData.revocation` 交给页面。账号切换或会话撤销时整个 QueryClient 和账本一起丢弃（原有机制，保持不变）。

### 1. 账本记录什么

| 来源 | 记录 |
|---|---|
| 学期/课程删除回执（`Deletion` 202） | 学期或课程本身被删；`cascade` 时其下所有课程/课堂也被撤销，`move_children` 只删对象本身 |
| `object.deleted`（`class_session`）事件 | 课堂被撤销 |
| `object.deleted`（`audio`）事件 | 该课堂某采集纪元的原音被撤权 |
| 权威拒绝：此前读到过的课堂详情 / 课程详情 / 复习资料，重读得到 `NOT_FOUND`/`GONE`/`FORBIDDEN` | 对应课堂 / 课程（仅对象本身）/ 资料被撤销 |

回执只带 `scope_type/scope_id`，不带被级联的课堂列表，所以受影响的课堂从缓存里推断（课堂→课程→学期，资料→课堂，转写版本→课堂）。同一对象在多个缓存里出现时以最新 `revision` 为准；同一 revision 互相矛盾时按“无法确定”处理，不写入撤销。`move_children` 回执带上接收位置，账本记下“旧课程→新课程”“旧学期→新学期”，之后删除接收位置时能认出缓存里仍挂在旧位置的子项。

### 2. 收到回执时立即清扫（不依赖重读）

对账号下每个缓存查询按种类判定，三种结果：

- **确定受影响**：详情类查询改成错误状态（合成的 `GONE`，页面显示“内容已被删除”），列表类查询过滤掉受影响的条目；
- **无法确定**（成员关系不在缓存里，例如复习资料库里某资料的课堂从未读到过）：整条查询丢弃（reset），联网时重新读取得到真实结果，离线时显示“无法连接服务”而不是旧内容；
- **确定不受影响**：保留。

“无法确定”只在应用新撤销的那一次清扫里、且只对这次撤销可能影响的成员关系按受影响处理（单节课堂撤销只影响课堂未知的资料/版本/快照；课程级联还影响课程未知的课堂；学期级联还影响学期未知的课程）。之后的守卫只处理确定受影响的内容，避免反复丢弃无关数据，也不会因为更早的级联去停掉后来绑定的采集。

被确定撤销的课堂、资料、转写版本 ID 会单独记在账本里：它们从缓存里被过滤掉之后成员关系就读不到了，晚到或重复的回复仍要能认出来。清扫时正在进行的请求，其回复落地时按这次撤销严格判定一次。

每个确定被撤销的课堂通知账号壳：撤销采集运行时里的该课堂（停止绑定的采集、作废未确认的上传、清掉实时字幕），清掉该课堂未确认的停止/暂停命令。绑定采集所在课堂只是“无法确定”时，只在本机停止采集（本机音频仍受关闭保护），不发删除事件、不在 Mock 服务端写删除标记；等重读或回执确认后才撤销。

### 3. 持续守卫

账本订阅 QueryCache：

- 之后进入缓存的任何数据（进行中的旧请求晚到、取消后的回滚、重读结果）再按账本过滤一次，过滤是幂等的；
- 任何查询的重读得到权威拒绝或 401 时，立刻去掉缓存里的旧 `data`；只有传输失败（`kind: 'network'`）才保留旧内容供离线只读，且只读回退期间页面上的服务端写操作全部停用；
- 本账号纪元里服务端读到过的课堂详情被权威拒绝时（即使缓存数据已被不确定的删除丢弃），按撤销课堂处理（替代原来的 `boundGone`）。从未被服务端读到过的课堂（PR-09a 演示课堂登记前）不会因 `NOT_FOUND` 被撤销；
- 已显示为“已删除”的查询之后离线重读失败，仍显示“已删除”，不改写成“无法连接”；
- Mock 场景整体替换数据集时账本清空（同一批 ID 背后的数据已换掉）。

### 4. 删除对话框

- 范围、方式、接收位置作为 mutation 变量提交，请求进行中锁住单选和接收位置；
- 回执在 `mutationFn` 内收到后立即交给账本（不依赖组件是否仍挂载、也不读重渲染后的状态）；
- 提交前先确认当前绑定采集所在课堂的成员关系（读课堂详情、学期删除时再读课程）。服务端此时说这节课不存在，说明它不是服务端课堂，不会被**这一次**删除影响（豁免只随这次请求）；仍无法确定时，回执到达后只在本机暂停采集；
- 删除请求传输失败或 2xx 回复无法读取（结果不确定）时，只丢弃可能受影响的缓存并取消进行中的读取（reset，不写入账本、不停采集），联网后由重读给出真实结果；服务端明确拒绝时什么都不改。

### 5. 页面

页面不再各自打补丁，只遵守一条规则（`features/data.tsx` 的 `readableCache` / `ReadOnlyWhile`）：没有失败、或最近一次失败是传输失败时才显示缓存数据，后一种情况附带刷新失败提示并停用服务端写操作；其他失败（权威拒绝、401、无法读取的回复）不显示任何私有内容。权威拒绝和 401 时 `data` 也已被账本去掉。10b 的 `evictClassroomFromReview`/`evictScopeFromReview` 删除。

## 测试

- 单元：`tests/revocation.test.ts`（5 个场景 + 晚到回复、取消订阅、离线重读不改写“已删除”状态），`tests/pr10b-domain.test.ts` 中原 10b 清理测试改为走账本、断言不变。
- 浏览器：`tests/revocation-receipts.browser.spec.ts`，每条删除在回复后立即断网，验证不依赖重读。
- 仅供浏览器测试的 Mock 控制（`localStorage`，不改 HTTP 契约）：`mock-test-offline-after`（某个写请求回复后传输层断网，页面不知情）、`mock-test-delay-path`（写请求延迟 1.5 秒）、`mock-test-fail-get`（某前缀的读请求按传输失败处理）；`__classroomMock.denyRevisions(id)` 让某资料的版本读取返回 `FORBIDDEN`。

## 不在范围内

- 本机草稿（课堂里输入但未提交的文字）不是服务端投影，不在清扫范围；
- 课程/学期的 `object.deleted` 事件（来自其他设备）不带删除方式，本次不处理，仍由重读处理；
- 真实后端、真实事件通道的集成留给集成 PR。
