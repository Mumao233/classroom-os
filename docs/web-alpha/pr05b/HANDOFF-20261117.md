## 真浏览器验证内容

- 原生 worklet 在 44.1 kHz/48 kHz stereo 输入下生成 mono 16 kHz PCM16，连续重采样与尾片输出分别为 7524/7510 bytes，逐样本量化最大误差为 0。
- 挂起 append 并持续输入，队列停在 64000 bytes，source 已断开，后续排队写没有继续调用 append，返回 `CAPACITY_EXCEEDED`。
- 浏览器以真实 HTTPS Cookie、单次 ticket 和 WSS 上传 32000-byte 整块与 514-byte 尾块，heartbeat 后继续合法上传，只有 durable 事务确认后清理本地内容。
- pause/resume 创建新 epoch，fence 增加。离线 stop 保留 pending 与幂等 intent，真实服务端 lease 过期后，重新创建 runtime、恢复封口状态、显式 recovery 授权并以 HTTP 补传成功。
- 旧 v1 缺失 `unresolvedCommands` 被规范为空数组，非法值拒绝。未知 renew 的原 key/body 在本地 stop 后仍保留。
- events WSS 原 ticket 与 logout 撤权行为通过，退出后关闭码为 1008。
- 两个独立真实登录从 HTTP 409 的既有 `error.conflict_id` 取得当前 owner 的 lease CAS 目标，明确确认后接管成功，旧设备实时命令拒绝。测试覆盖并发同 CAS 仅一方成功、过时 CAS 拒绝、错误 device/匿名/跨 owner 不泄露 ID。两个独立 Chromium context 使用实际 CaptureClient 完成同一闭环，联合 08 另验证合法/非法 conflict 字段的八个变体。

A 的 WSS/PCM browser harness 使用内存 cache port，验证真实服务端传输和恢复。B07 联合 harness 使用真实 IndexedDB/Web Crypto 与合成 transport，验证两包的持久化顺序、刷新恢复、durable cleanup 重试、租约/generation、删除与身份失效接口。二者的证据分别记录在各自 JSON。

TLS 使用本轮 server key 的 SPKI allow-list。没有修改 OS 信任库，证书链与 hostname 的完整生产验证仍未覆盖。没有真实麦克风、生产录音、provider 或付费 API 调用。
