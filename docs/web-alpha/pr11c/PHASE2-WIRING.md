| Mock | `/search`、`/notifications`、`/feedback` 交给第一阶段的 search-backend，命中每次请求从工作台账号的现有数据计算：有效课程与课堂、复习文档的采用稿和最新个人稿（两者都可搜，未采用的 AI 候选不可搜）、当前有效转写版本的正式段。按 SQL 搜索的字段与顺序先匹配完整字段（含卡片正反面、缺失材料说明等结构化内容），再与 SQL 一致取命中前 60 字起的 300 字作片段；转写段只按自身文本匹配。单个修订读取与修订列表执行同一来源权限检查。任务完成通知只依赖任务和课堂，课堂移到别的课程后仍可见；课堂不再有效时隐藏。首页样例通知的消息码有各自的标题 |

## 设计决定

- **地址中的关键词绑定账号代际。** 账号切换时，运行时状态变化会同步重挂应用外壳，而 React Router v7 的导航在 transition 中稍后提交。下一个账号因此可能先挂在上一个账号的 `/search?q=…` 上，并自动用对方的关键词搜索、把地址改回 `?q=`，覆盖“回到首页”的导航（浏览器测试曾复现）。现在本页写入地址的关键词带 `searchAccount` 状态，只有无标记（直接打开或外部链接）或标记为当前账号时才自动搜索。
- **地址关键词由外部改变时重建表单。** 路由在 `/search` 间导航时保留页面实例；关键词不是表单自己写入的（页眉链接、后退、前进）就换一个新表单，避免地址与结果不一致。
- **反馈是页面而不是弹窗**，与 02 路由表一致；片段仍须单独勾选确认，默认不附带。
- **离线搜索仍只显示范围提示。** `TrustedCache` 尚无按授权代际枚举学习条目的安全接口（第一阶段交接已记录），未接入本地缓存搜索。
