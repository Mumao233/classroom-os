## 06a 交给 06b 的验收清单

1. **同一个供应商实现。** 06a 在五方法后封装连接、事件解码、标识映射、deadline 和关闭。先向可注入的离线 transport 输入脱敏 wire fixtures，覆盖错 task、坏包、重复/乱序句子、缺终态、读写失败和累计 usage；独立断言另验输入零外发。06b 复用该实现、fixtures 与模拟器作为回归基准，自己的测试替换 transport 即可。当前已有的仅是 Simulator 与模拟用例。[模拟器](../../../web/backend/classroom_web/asr_sim/simulator.py) · [模拟语义与限制](README.md)
2. **可验证的映射和权限。** 交接工件列出具体字段路径、单位、身份生命周期、修订和错误含义，覆盖发送前后、finish 后的尾句和 query 能力。供应商 task_id 不直接充当本地身份或权限证明。03b 的浏览器 WebSocket ticket 与供应商凭据分属两段连接。06b 对外沿用 `createAsrStream/getAsrStream/finishAsrStream` 及 `transcript.partial/final`；事件协议版本为 1，OpenAPI 包版本为 0.2.1。[OpenAPI](../architecture/contracts/openapi.json) · [事件 schema](../architecture/contracts/events.schema.json) · [状态机](../architecture/contracts/state-machines.json)
3. **两个层级的证据。** 06a 的真实接口验证先固定 SHA、库/API 版本、样本 hash、已批准账户及上界；在专项批准后留存逐连接的脱敏收发序列、样本范围、结束/清理、账单与原 attempt。06b 再以采集回执、持久 dispatch、PG 费用记录和可重放 final 验收并发、崩溃、跨窗口及尾帧。06a 的短连接成功仅能支撑对应的协议事实。[真实接口计划](REAL-API-PLAN-20261117.md) · [费用接入记录](../pr11a/INTEGRATION-REVIEW-20261115.md)

## 依赖、歧义与待决事项

- **DAG 和包名。** 06a 硬依赖 01；付费还依赖 03b、04a、05b、11a 以及专项授权、TBD-01/02。06b 的硬依赖为 02b、05b、06a、11a。按上述分工实施不需更改 DAG、ADR、包名或公开 schema。合并了基础模块仍需独立满足相应启用与验收条件。
- **流、采集 epoch 与恢复。** A4 的“重连新epoch”摘要与架构 04 的“供应商流断开后建立新 stream_id”、05b 的采集租约/epoch 描述粒度不同。06b 的验收用例应分别覆盖仅供应商断线（新 stream，仍引用原 durable capture epoch），以及设备接管、恢复/新采集 epoch（保留各自归属和偏移）。若要求供应商断线本身轮换 capture epoch，先由架构与采集方审定其兼容性。
- **需要人工确认的变更方案。** 若提议以三条短流关闭 file/stream、热词 A/B 或 30 段/长时联合门禁，应提交 06a/12b 的逐项验收分配及仍待交付清单。若单 request 要跨多个 reservation，应提交 11a/06b 数据模型提案，说明窗口、attempt、原 request、累计高水位/差量、迟到更正及历史账本迁移。若需新增公开字段或改状态语义，先列明 producer/consumer、兼容性、版本和正反 fixtures，经架构复审及人工确认。现有单窗约束与发送门禁继续生效。
- **下一项开发工作。** 在 PR-06a 内补齐一个默认离线、无凭据、单连接的 wire 替身与可复用协议解析，优先核对 task/句子身份、finish 后剩余事件及费用缺失如何上报。短 POC 的价格、授权与有效独审须在真实连接前闭合。06b 的持续流、持久恢复、跨窗和正式课堂链路留给其单独授权。
