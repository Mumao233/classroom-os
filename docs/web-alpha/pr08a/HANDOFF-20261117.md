## 独立复审修复

Astra 检查发现可变入参导致的两项 P1，并由主控分配修复。

1. durable ACK 读取期间，调用者修改 receipt.descriptor 可能改删另一个块。入口冻结 receipt，读取和删除贯穿同一 descriptor，删除条件绑定稳定 scope/object/class。
2. hash 期间调用者重用 PCM 缓冲或修改 descriptor/祖先可能造成持久内容与校验不同。入口冻结全部输入，hash/加密用同一快照，临时副本最终清理。同根因的通用 put 重试比较也改用冻结明文。

额外修复包括 unlockScope 成功事件回调引发登出时的迟到 epoch 登记，以及 devices/key response 的 epoch 一致性校验。Astra 增量静态复核确认上述修复，真实浏览器回归单列记录。Astra 建议增加关闭 BroadcastChannel 接收时的持久失效屏障验证，已加入第二轮。
