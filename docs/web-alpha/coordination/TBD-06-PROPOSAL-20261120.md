## 1. 通用规则

- **单位采用十进制。** 1 MB = 1,000,000 bytes，1 GB = 1,000,000,000 bytes。旧包 2 GiB 与 Web 上限比较时统一换算为字节。
- **超限一律显式拒绝。** 复用现有错误码 `CAPACITY_EXCEEDED`、`QUOTA_EXCEEDED`、`RATE_LIMITED`、`GONE`。错误中需要说明超了哪一项时，按版本化方式扩展 `Error` schema。不截断，不部分提交，不静默淘汰唯一副本（CF-11、CF-17）。
- **集中配置。** 数值进入版本化策略 `tbd06-v2`，写明每项的计量对象、计数口径和生效时间。前后端读同一份配置，服务端为最终裁决方。
- **降额不删数据。** 策略下调后，已超额的账号可以读和删，新增写入被拒绝，不触发任何自动清理。

## 2. 媒体（PR-04a）

| 项目 | v2 初值 | 相对 v1 的变化及理由 |
|---|---|---|
| 单张图片 | **维持 16 MB** | v1 的 20 MB 需要改传输时限，收益很小 |
| PDF/PPT 文档 | **Alpha 不提供** | 现有契约用途只有 `slide`、`import_package`。新增文件类型需要完整数据模型，留待后续产品变更 |
| 问答与 Review 上下文 | 维持现有各 16 MB 总预算 | 图片能存下，不等于能整张送进模型 |

## 3. 导入导出包（PR-08c）

大包不再走单次请求。导入包按 **16 MB 分片上传**（复用现有单对象上限和时限），服务端组装后逐片校验并做整包哈希。导出包通过现有 Range 下载按段取回，每一段都要重新做授权检查。

| 项目 | v2 初值 | 说明 |
|---|---|---|
| 导入包压缩后 | **500 MB**（v1 为 1 GB） | 上下限与导出对称，导出包可以原样再导入 |
| 导入包解压后 | **1 GB**（v1 为 2 GB） | 旧包超过此值时整包拒绝，并提示拆分 |
| 导出包 | **500 MB**（v1 为 2 GB） | 与导入压缩上限一致；超出时拒绝，并提示缩小范围 |
| 原样重导承诺 | **只对聚合 ZIP（`PACKAGE_SCHEMA`）承诺** | 导出器在生成前按导入侧全部上限自检（展开大小、文件数、深度、压缩比、解析预算），任一项不满足就拒绝导出并提示缩小范围，不生成无法重导的 ZIP。JSON、Markdown 只用于阅读，不承诺可导入。每种 scope 都要用实际导出器做回环验证 |
| 文件数 | 10,000 | 只计常规文件，目录不计 |
| 路径深度 | 32 级 | 按路径分隔后的段数计。拒绝绝对路径、`..`、链接和设备名 |
| 压缩比 | 单条目和整包均不超过 100:1 | 分母为压缩后字节数 |
| 元数据 | JSON/manifest 合计不超过 64 MB，单个 JSON 不超过 16 MB | 测试候选值 |
| 单图像素 | 不超过 50 百万像素（约 8000×6000） | 测试候选值 |
| 整包总像素（解码工作量） | 不超过 4,000 百万像素 | 以解码总像素作为解码工作量的计量。测试候选值，压测不过就下调 |
| 原始录音 | **Alpha 不导出** | 若请求带 `include_audio=true`，明确拒绝；前端隐藏该勾选项，并同步修改说明文字 |

### 3.1 分片与续传（PR-08c 起草契约）

分片上传另起一套独立协议，不复用 `import_package` 的整包签名检查。协议至少要包含：分片序号和偏移、分片长度（最大 16 MB）、逐片哈希和整包哈希、同一操作键的重试幂等、缺片或重叠时拒绝、组装后流式校验整包，以及取消后清除全部分片。字段级契约由 PR-08c 起草，经 Astra 审查后冻结。

## 4. 并发（PR-08c）

| 项目 | v2 初值 |
|---|---|
| 每账号 | **同一时间只能有 1 个导入或导出任务**，不允许一进一出同时进行 |
| 平台 | 同时运行 4 个任务。第 5 个直接拒绝（`RATE_LIMITED`，附带建议的重试时间），**不排队** |
| 占槽口径 | 从预检开始占槽，到完成、失败、取消或过期时释放。槽位记在 PostgreSQL 里，进程重启后可以恢复；同一个操作键重复提交不会多占一个槽 |
| 等待确认 | 预检完成、等待用户确认的任务**最多占槽 30 分钟**，超时释放槽位。暂存保留到 24 小时截止；用户之后再确认时，必须重新预检并重新申请槽位 |
| 槽位租约 | 执行中的任务按租约占槽，由 worker 心跳续期。心跳停止 5 分钟后，系统回收槽位，任务标记为失败待清除。只有系统回收流程和持有租约的 worker 可以释放槽位 |
| 预检前暂存 | 每账号同一时间最多 **1 个**未完成的导入上传（含分片）；平台导入暂存合计不超过 **5 GB**，超出时以 `RATE_LIMITED` 拒绝新上传 |
| 导出产物累计 | 每账号同时最多保留 **1 个**未过期的导出包，生成新包前须等旧包过期或由用户主动删除；平台导出产物合计不超过 **5 GB** |

## 5. 期限与撤权

| 对象 | 访问截止 | 物理清除 |
|---|---|---|
| 导入暂存 | 从**创建上传**起 24 小时（覆盖从未预检的情况）；预检不延长期限 | 从访问截止起算 |
| 导出包 | 从**成功发布**起 24 小时 | 从访问截止起算 |
| 主动撤权、取消、失败 | **立即**截止访问 | 从截止时刻起算 |

物理清除的时钟统一**从访问截止时刻起算**：目标是 **24 小时内**清除完毕，与 04b 主存储的 24 小时物理清除目标一致；超过 24 小时未清除就告警；**72 小时是故障处置的硬上限**，超过即升级为事故。正常到期的情况下，从创建或发布到清除完毕最长 48 小时。

课程删除或权限撤销后，每次下载授权、每个 Range 分段以及续传都要重新检查权限，曾经下载过的包也照样拦截。下载票据的到期时间取以下三者中最早的一个：`签发时间 + 60 秒`、会话到期时间、对象访问截止时间。票据过期后，客户端重新申请票据即可继续，但必须绑定同一对象版本；对象版本变了、已过截止时间或已被撤权时，一律拒绝，不能接着续传。账户或课程级的聚合导出包需要记录完整来源关系，任一来源被撤权，整包失效。

## 6. 云端存储额度

v1 定的每账号 5 GB **Alpha 暂不实施**。PR-11a 现在只有周期用量配额，存量字节额度需要新建一套账本，包括已用、预留、释放，以及各类对象如何计量。Alpha 期间改为：

- 记录每账号的存量字节用于观察，不拦截；
- 由第 3 节的包上限和第 4 节的并发上限控制单次增量；
- 平台总用量超过运维设定的阈值时告警。

正式开放前另立项设计存量额度，不能拿 ASR 时长额度来推算字节额度。

## 7. 浏览器本地

| 存储池 | v2 初值 | 计量口径与满额行为 |
|---|---|---|
| 学习缓存 | 14 天 / 20 节 / 50,000,000 bytes | 不变 |
| 草稿 | 20 MB，`draftOperations` 统一默认 **2,000** 条 | 按 08a 现有公式计量（密文 + nonce + AAD），不另计 IndexedDB 物理元数据。达到 80% 时提示；满额时拒绝新写入，已有草稿不丢 |
| 录音恢复队列 | 1 GB | 按 08a 现有公式计量（密文 + nonce + AAD）。裸 PCM 的理论值约 8.68 小时，这只是**容量估算**，实际可用时长以写满和恢复测试的结果为准。达到 80% 时警告；满额或写入失败时，**按 05b 现有路径安全停止**，报告缺口并保留已存的块 |
| 准入估计 | `estimate()` 可用空间不少于 300 MB 才开始录音 | 只作为准入参考；估计值不可用时，以实际写入结果为准 |

录音恢复按 CF-11 的边界执行：在未信任设备上，可以凭本次单独的 consent 使用录音恢复，不要求可信设备。**删除 v1 中“空间不足时仅在线识别继续”的说法**。现有流程是先持久化再发送，空间不足时只能安全停止。

“清空缓存”只能清学习池，**不能调用现有的 `purge()`**，因为它会清掉整个账号/设备命名空间。需要新增一个只作用于学习池的清理入口。

1 GB 队列大约有 31,250 个一秒块。必须实测接近满池时的写入延迟、内存占用和恢复耗时，达不到要求就下调。

## 8. 关闭顺序

采用 Astra 建议的顺序：**先冻结候选契约与 `tbd06-v2` 策略，再按该版本验收，最后签署。** 冻结前先跑四条关键用例：500 MB 导出原样重导；四个预检停在确认页时第五个请求的行为；到期或撤权发生在 Range 续传中途；真实 IndexedDB 写满后的安全停止与恢复。 测试分五组：契约边界、大包与并发、浏览器满额与恢复、账本与可控时钟、签署汇总。具体用例和通过条件见 Astra 审查结论。

## 9. 影响范围

- PR-04a：上限不变；Range 下载用于导出分段取回。
- PR-05b、PR-08a：录音和草稿的计量口径、80% 提示、安全停止、新增只清学习池的清理入口。

- PR-11a：Alpha 不改动；存量字节额度在正式开放前另行设计。
