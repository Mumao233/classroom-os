# PR-03b R05：Alpha 范围的账号枚举防护论证

日期：2026-11-12（America/Los_Angeles）。负责人：林珈诚。工作包 PR-03b；本记录没有 GitHub PR 编号。依据 [验收范围收窄决定](SCOPE-DECISION-20261112.md)。

**结论：设计上登录不区分已知与未知账号，小样本实测未见可区分差异。这不是原统计标准（BA/AUC 上界 0.55）下的通过；原 campaign 未执行。**

## 设计论证

登录入口 `AuthService.login`（`web/backend/classroom_web/application/auth.py`）对两类账号走同一条路径：

| 环节 | 已知账号 | 未知账号 |
|---|---|---|
| 账号失败预算的键 | `owner_id` 的承诺值 | 规范化邮箱的承诺值 |
| 预算规则 | 3 次/900 秒 | 相同 |
| 预算耗尽 | 验证前返回 429，不做哈希 | 相同 |
| 密码验证 | 对存储的 Argon2id PHC 做完整验证 | 对公开占位 PHC 做完整验证，参数同为 64MiB/t3/p1 |
| 失败响应 | 401 `UNAUTHENTICATED` | 相同 |
| 来源失败预算 | 20 次/60 秒，同一计数 | 相同 |

占位 PHC 定义在 `auth_crypto.py` 的 `Credentials.dummy`，不含任何账号秘密，也不接受调用方指定的成本参数。预算键使用带密钥的承诺值，数据库里不出现明文邮箱。

## 小样本实测

测试：`web/backend/tests/integration/test_enumeration_parity.py`。真实合成 PostgreSQL 17.11，经真实 ASGI 路由；3 个已知账号和 3 个未知邮箱，各做 3 次错误密码登录加 1 次超限尝试，两组交替执行并轮换先后顺序。

断言内容：

- 两组每一次尝试的状态码、响应体结构、错误字段、响应头集合和 Cookie 集合完全相同。
- 前 3 次各触发恰好 1 次 Argon2 验证，第 4 次返回 429 且触发 0 次。
- 两组哈希耗时中位数之比、请求耗时中位数之比都在 0.5 到 2.0 之间。这是粗粒度防护，用来发现某一组被跳过或缩短哈希，容忍虚拟机噪声。

2026-11-12 在 VMware 来宾（Windows 11，4 核 8G，Python 3.12.14）内的实际结果，broker 任务 `parity-01`，退出码 0：

| 指标 | 已知账号 | 未知账号 |
|---|---|---|
| 每组样本数 | 9 | 9 |
| 哈希耗时中位数 | 104.60 ms | 103.72 ms |
| 请求耗时中位数 | 119.65 ms | 117.79 ms |

## 限制

- 每组 9 个样本不能支持统计结论，也不能排除远程攻击者用大量样本测出的微小时序差。
- 只覆盖登录入口的错误密码路径；忘记密码、注册和邮箱变更入口的枚举面未在本测试中度量。
- 测试经进程内 ASGI 客户端发起，不含真实网络和 TLS 抖动。
- 原 schema 3 预注册方案（108 分层、每组 1000 下限、自然等待 900 秒）及其工具保留在 `tools/pr03b/`，状态为未执行。
