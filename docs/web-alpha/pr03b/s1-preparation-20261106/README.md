## 3. 这次补齐什么

技术推荐采用小规模可维护方案：复用既定 FastAPI/Python 3.12/PG17，不增身份平台；D0 用独立固定 pin/外部当前高水位、恢复与维护分用途；限流先审 PG 原子计数/全进程有界哈希预算，避免新增不必要服务；本地版本化名单原子发布；身份通知走独立内部路径；status 用最小持久事实和当前资格；恢复码交付后置。各自可实施条件及备选详见技术文档，不能据此跳过独立审定。

实验计划分为真实隔离 PG/HTTPS/WS/本地邮件/受限命令的功能安全证据，以及声明硬资源上限的容量证据。拟参考负载为 30 个合成用户、30 条 WS、业务 10 req/s、登录 1 req/s，Argon2 并发筛选 1/2/4/8、突发 16/32；均为待审工作负载，不是吞吐承诺、生产默认或部署采购决定。安全拒绝和秘密不泄露必须逐例零违规；p95/p99、内存余量、过载恢复等目标另列，性能不足不能降低安全要求。

本包把 R01 的时间措辞落实为两个阶段：验证时 `verified_at < challenge_expiry`；写执行时实际 DB 时钟 `< operation_deadline`，并重核当前资格/pending。已合法消费挑战后，不以它后续到期否决有效 fresh 操作证明；到期/旧证明也不能借新 nonce 续时。该表达沿用 D02 CLOSED 结论，不创建政策例外。
