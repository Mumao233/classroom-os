### 2.1 A04：必测区分与留出判定

A04 的本次修订将**必测独立留出**区分检验设为通过门禁，分位等价只保留为辅助，不能单独取得 PASS。不要求复杂机器学习：必测公开端到端响应时长的简单阈值，同时覆盖两种攻击方向；对于重复请求，必测同一目标完整序列的 mean/median 聚合分数及其简单阈值。服务端内部耗时仅供诊断，不能减去某臂独有的排队、限流延迟或网络开销来制造不可区分。

比较“存在且 active 账号＋错误密码”与“不存在账号＋同成本 dummy verify”，PHC 成本、输入长度、角色策略匹配；pending/disabled 另分层，角色、长度、冷/热和负载的各必测分层分别报告。采样前登记可公开观测的特征（端到端时长、响应状态/长度等）、所有分层、阈值拟合准则、两种方向、聚合分数、请求时序、预算和统计判据。阈值及其方向只在校准集确定并冻结；不得用留出数据调参、换方向、选择最有利的聚合次数或删掉不利分层。额外分类器只能补充，不能替代以下简单攻击必测项。

本次待审方案规定 **k=1/2/4/8** 均必测：k=1 是单次阈值，k=2/4 是限额前重复聚合，k=8 覆盖真实预算耗尽后的序列。每个序列始终针对同一个已知或未知目标，不能每次换未知标识规避账号预算。序列的请求计划与最多 30 分钟威胁窗口预先登记；真实账号/来源/跨入口限流、退避、拒绝和超时全部保留，不在序列中重建实例、清预算、伪造来源或关闭限流。k=8 不能为凑齐八次昂贵验证而跳过第五次起的退避；聚合使用完整公开响应序列，并同时检验状态、长度、拒绝位置及等待时间等泄漏。组内合法停止/超时规则和聚合表示在校准前固定，不能剔除拒绝样本后假称是攻击者完整可见数据；无法在声明的真实规则下获得所需证据时记 INCONCLUSIVE。

校准与独立留出按完整 trial、目标标识和时间块分割，同一目标的重复请求及同一 trial 不跨两集；如果多个 k 共用长序列前缀，整个长序列必须归同一集合，并在置信计算中保留其相关性。原始观测每臂至少 5,000 作为底线，同时每个分层、每个 k 的**校准集和留出集各至少 1000 个独立序列组/臂**；按较大的样本需求采集，不把 k 个请求当 k 个独立样本。组相关或配对 trial 的置信区间按完整序列/trial 计算；缺组、有效独立样本不足或区间方法不能支持尾部置信度均为 INCONCLUSIVE。

每个必测分支须报告冻结阈值在留出集上的 balanced accuracy，以及预登记连续时长/聚合分数的双向区分指标 **AUC* = max(AUC, 1−AUC)**，避免反向 AUC 很低却被当成安全。所有分层、k、方向和分数组成采样前固定的比较族，使用族内 **95% 同时置信区间**（或预登记 Bonferroni 等校正），不能逐项 95% 后挑选最有利结果。只有各必测分支 balanced accuracy 和 AUC* 的同时置信**上界均≤0.55**，并且辅助分位等价达标、其他零容忍项通过，才支持本测试范围内的 PASS；不得平均掉泄漏分支。判定优先级为先判 FAIL：稳定可重复区分，或任一必测区分能力同时置信下界>0.55，即为 FAIL；在没有 FAIL 的前提下，缺检验、证据不足、区间跨门槛或上界不能证明≤0.55 时为 INCONCLUSIVE，均不得 PASS，不能把已证泄漏降为不明。上述界值仍为待独立审定的 S1 判据，不能证明现实世界绝对不可枚举。

辅助分位检查继续分列两臂 p50/p95 差值的 90% 置信区间，要求整体落入 `±max(5ms, 基准分位×10%)`，基准取该层错误密码控制臂。它只检查量级，不能覆盖或取代区分门禁。静态反例中两臂若稳定在 299–301ms 与 319–321ms，校准的简单阈值约 **310ms** 即可分开，独立留出 balanced accuracy/AUC* 接近 1，必须 FAIL；即使约 20ms 差通过分位辅助界，也不改变结果。这是判据的静态推导，本轮没有生成样本、拟合分类器或运行认证实验。正文、状态、长度及错误映射中的未批准存在性差异仍为零容忍，不因任何统计达标豁免。

已准入验证时序与真实限流耗尽两组证据分列，前者不能混入廉价拒绝来制造快速等价。独立 trial 可在受控测试 setup 中创建自己的 disposable 数据库/应用实例、至多 30 个合成活跃账号；开始采集前就启用全部真实预算及 CSRF/preauth/验证链，**同一序列开始后不得重建**。只可在完整 trial 之间按预登记计划重建，且初始化/cache 条件须分层留证，不能把新实例结论称作同一实例长时成绩；另须用不重建的连续实例覆盖跨入口/跨进程耗尽、退避与恢复。样本成本不足时如实记 N 和 INCONCLUSIVE，不删除限流门禁补样本。

## 3. D02、D03、N01/N02 的专项验收谓词

### 3.1 四时间分两个阶段判断

对 issue 和 manual complete 分别记录独立 challenge、实际服务端 verified_at、固定 operation_deadline、存在时的 pending_flow_expiry，并绑定本次动作、case/目标 role 与 epoch、actor/authority、deployment、计划、接收端和 flow；complete 另绑新因子及确认摘要。验证时间来自服务端实际完成全部因子、签名与绑定检查成功的 DB 时钟，不能延后重置旧 verified_at。

1. **验证阶段：**实际全校验成功时须 `verified_at < challenge_expiry`；等于边界拒绝。5 分钟只是 challenge 等待期候选。
2. **执行阶段：**形成不可篡改证明时固定 `operation_deadline <= verified_at + 120秒`，再取当前资格、证明及已有 pending 截止的更早值。取得**所有**必要锁后用实际 DB `clock_timestamp()` 检查 `now < operation_deadline`，并重核当前资格、scope、flow 和 pending；等于或超过边界拒绝。此时不再以已合法消费 challenge 的 expiry 再截断该窗口。

10 分钟只是 pending/flow TTL 候选，不续操作授权，也不自动续 pending。issue 单次消费自己的批准 nonce；complete 消费 fresh completion_nonce 与有效 cap，不重复消费已经用于 issue 的 nonce。原 issue 证明过期但 pending 有效时，允许原执行者用新资格、新证明、新 nonce 完成；不得复用旧批准或要求先取得已丢失的 Web MFA。

边界覆盖 deadline 前、等于、后，以及验证四分钟后执行、challenge 4:59/5:00、锁等待跨 120 秒。可控时钟仅用于隔离服务的受审测试 seam，不能改变机器全局时间或生产校验；另须真实 DB 计时的锁等待证据。建议跨 120 秒专项采用事务局部 `lock_timeout=180s`、`statement_timeout=210s`、harness watchdog=240s，以 barrier 在 verified_at 后真实跨至少 121 秒才释放阻塞锁。记录实际时钟、等待起止、锁集合和退出；普通用例不沿用这组长超时。所有值仍待环境/方案审定，不能只 sleep 后推断实际等待成立，也不能因默认较短 timeout 先失败而冒称已验证锁后新鲜度。

### 3.2 status 的事实、线性化与副作用

原稳定 actor/authority 以当前资格 fresh 认证，只查 stored_executor_type/id 绑定的本人 case/op；cap 消费、目标 epoch 提升或目标旧浏览器失效不破坏查询路径。执行者撤权、其他 Admin、旧 cap 或仅知道标识仍拒绝，且不泄露他人 case 是否存在。

committed 必须读到与最终变更同一事务提交的 op 最小事实及一致 case 状态；not_committed 只在真实 PG 对本人 case/op 取得所需共享锁、锁后及返回前核对当前资格和 status proof 期限，并在线性化点能证明指定 op 尚未提交且 pending 有效时报告。记录最终事务/查询/撤销的提交顺序及锁，不能从“没找到行”推定未提交；未知 case、PG 故障、并发状态或证据不足一律结果不明。释放读锁后事实可能变化，not_committed 不授权重做。

重复 status 的恢复业务写增量、恢复 nonce/cap 消费、factor/epoch 变更、通知、重签、finalize 及秘密返回均为 0；必要独立鉴权/准入日志单独列出。再次执行是另一个 fresh≤120 秒、操作绑定、单次授权的写动作，锁内重读当前 case/op/flow；completed 拒绝再切换。S2 须冻结最小响应、受限角色/查询函数和错误兼容，不能从此文推断新 status API 已存在。

### 3.3 独立通知和新恢复码

N01 的完整锁图须包括生产者、领取者、投递/回查者，及所有 FK、UNIQUE、trigger、审计、清理函数的隐式锁；列同一连接/事务、锁强度、对象、顺序和释放点。安全控制面只写独立 identity 内部事件，不竞争业务 owner counter/Outbox。生产者在按序锁 user/authority/case 后插事件；领取者只锁自身事件，提交释放后才另事务读当前授权，禁止持事件锁回取 user。不能笼统改弱 user 锁，现有 identity_events 的激活唯一约束不能假称已支持重复撤销。

A45须用真实双连接重建原反例的持锁前置交错：L持已有业务counter，插Outbox时owner FK请求users KEY SHARE；S持users FOR UPDATE。证明新S只写identity事件、不等待L的counter，S提交后L可完成；生产、领取、投递及失败重试也须覆盖两种启动顺序。采用第2节专项候选lock/statement/watchdog=5s/10s/15s，预登记barrier释放后两连接均≤10s完成；通过要求为deadlock数0、无反向锁序、变更/审计/事件原子、无秘密、无Provider重发。若用故意反向的历史坏路径作对照，必须单独预登记期望异常并分列，不把它与新路径混报“全部无死锁”。S2先审锁图与验收方案，真实证明留获授权的实现验证，不能把设计图当执行成绩。

N02 的 final 原子废弃旧恢复码组，生成/返回新组数均为 0；status、CLI 和旧 cap 取码均拒绝。完整密码＋新 MFA 重新登录后，按独立显式生成/轮换及所需近期证明产生新组，合法接收端只展示一次、no-store、只持久化摘要。分别断开 final 和新组生成响应：前者查独立 status 不重做 final；后者不回放原码，按受审显式轮换处理。新组尚未生成的提示、一次展示和丢响应规则继续进入 S2 契约审查。
