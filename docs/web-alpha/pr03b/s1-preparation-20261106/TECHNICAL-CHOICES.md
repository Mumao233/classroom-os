## 2. 技术建议

### T01 — D0：固定公钥 pin 与独立当前高水位

- **推荐与依据：**沿用 D01 已闭合的授权链。首次安装先由外部既存资源 owner/部署 IAM 及项目用户的独立安装批准授权，具名维护者核对实际人，再固定 deployment、authority、OS/key 映射、R0、K_change 和验证器版本。Alpha 优先采用固定公钥 pin 加既有受控部署审计。外部账本保存初始化完成、最高版本/hash、撤销墓碑及已接受变更 nonce；该状态不能随应用 PG 备份回退。
- **替代与取舍：**若目标平台已有可核验的签名部署/不可回退配置能力，可复用；不为本功能新建通用 PKI。仅“清单验签成功且与 PG 相同”或缓存旧签名快照均不够，必须核对独立账本的当前高水位。不能用可写 PG、待批清单、新 key PoP 或缺失高水位后的重新初始化授权。
- **S1 需审定：**接受“独立当前状态、只前滚、错配拒绝”的方案边界；合成模型分别覆盖账本接受、PG 提交、只读清单发布三阶段及任一点中断。新鲜度必须能够拒绝旧证据重放，不能只写一个允许缓存时长就声称排除 PG 回滚。D0 当前尚未真实建立。
- **S2/启用前细化：**具体平台提供何种高水位/当前性证据、受限读取与部署维护 ACL、规范签名、nonce 预留、幂等前滚、共同 deployment_guard 与 PG 提交线性化、服务重启和数据库恢复后的拒绝门。外部证据准备不持 PG 锁跨网络；S2 必须证明锁内使用的证据与当前控制状态一致。根全失/外部批准不可验证继续关闭，重建另审。关联 **A32、A33、A38–A40**。

### T02 — 本人运维身份：OS peer 加独立现场签名，三种用途分离

- **推荐与依据：**受限本机控制服务从操作系统取得实际调用主体，结合预登记独立签名校验；不能相信 CLI 传入的用户名/authority 字符串。R0 验清单、K_change 批准登记维护、K_recover 证明本人恢复分别分域、分权限与凭据保管。算法优先评估成熟组件的 **Ed25519**，签名覆盖用途、部署、actor/authority、case/op、目标/版本、计划摘要、nonce 与期限。
- **替代与取舍：**Linux 可评估 Unix socket peer credentials，Windows 可评估受限 named pipe 与 OS token/SID；它们是合成环境候选，不表示已选择真实平台。平台或受控密钥设施不支持 Ed25519 时可提交成熟替代算法的兼容/签名格式方案。固定硬件数量、SSH CA 或共享 root 均不是本轮要求；同一自然人持不同用途凭据不等于合并权限。
- **S1 需审定：**选择合成平台适配轮廓及组件评价标准；签名应显式经本人确认操作内容，不能把后台自动签名或 Agent 代执行作为人工 complete。验证新 key PoP 只证明控制而不授登记权。
- **S2/启用前细化：**peer 验证 API、不可伪造主体映射、通道 ACL、成熟库/版本、规范编码与分域、当前 key 撤销/轮换、受限服务和维护者权限矩阵。真实人映射、凭据形态及保管/全失处置在启用前登记，不在聊天收集。关联 **A18、A31–A33、A37–A40**。

### T03 — 本地密码名单：可追溯来源、完整性、陈旧期与原子切换

- **推荐与依据：**准备“本地常见弱密码精确集合＋经审查的泄露密码本地哈希数据集”两类离线输入；泄露数据候选可评估 Have I Been Pwned Pwned Passwords 的可下载数据。这里只提出来源候选，**未下载、未核验当前许可/分发条件或声称已有名单**。哈希匹配仅用于名单查找，不替代 Argon2 密码存储；密码或其可关联查询不发送外部服务。
- **替代与取舍：**若候选全量数据不适合目标磁盘/内存预算，可另审覆盖范围明确、版本固定的本地子集或其他合规数据源；不能用空名单、未声明覆盖缩水或仅在线查询代替已确认政策。布隆过滤器可作预筛，最终拒绝宜由精确集合确认，避免把无界误报当政策。
- **S1 需审定：**建议每日尝试取得更新，批准快照最大陈旧期 **30 天**；两者均为本次新待审建议，需依据来源发布节奏、资源与风险审定。包清单固定来源标识、获取/发布时间、适用规则、版本、条目/字节边界及 SHA-256；可信来源获取与本地受权批准共同锚定 hash，单独附带 hash 不自证真实性。
- **S2/启用前细化：**下载/校验在旁路暂存，完整性与格式验证通过后以不可变版本原子切换 active 指针；防旧版本回滚。设置密码的事务记录并在提交前重核名单版本仍获准且未过期/撤销；切换后的并发请求不能用失效版本成功。更新失败但旧版本有效可继续；无有效版本则 register/change/reset 安全暂停，不消费 reset/reauth 证明、不留下成功 Receipt；正常 login 仍验证既有 PHC/MFA。ACL、错误与重试语义、异常大小及清理由 S2 审。关联 **A01、A02、A14、A24、A30**。

### T04 — Unicode：按 code point 计数，保持输入原样

- **推荐与依据：**三个新设密码模型按 Unicode code point 计数；学生 6、管理员 12 为既定最低值，公共上限 1024 沿契约差异待 S2 审。建议拒绝未配对 surrogate/非法 UTF-8；不 trim、截断、大小写折叠或静默做 NFC/NFKC，组合字符按其实际 code point 数计数。前端使用相同语义，服务端仍为权威。
- **替代与取舍：**grapheme cluster 更接近视觉字符但与现有 JSON Schema/后端计数不同，不推荐本阶段改用。若规范化将来被提出，须单独审查历史 PHC 与兼容，不能悄悄重写密码。
- **S1 需审定：**确认非法编码拒绝、无规范化及按 code point 的测试语料；建议认证 JSON 原始请求体上限 16 KiB，在昂贵校验前拒绝超限，覆盖 1024 个补充平面字符及 JSON 转义膨胀。该上限是本次待审传输预算，须由 S2 逐路由核对完整字段，不是把密码逻辑上限改成字节数；不把新设最低值套到 login/reauth 的既有凭据验证。
- **S2 细化：**三个字段、两个既有 hash/register 入口、后续 reset/change、客户端计数及正反 fixtures 一致更新；名单使用与已输入密码完全相同的编码语义。关联 **A01、A03、A04、A27**。

### T05 — 会话活动与 touch：同事务授权、明确活动集合

- **推荐与依据：**先采用同一短业务事务检查账户、唯一 security_epoch、device/session 与期限，并按是否需要 touch 从第一次取得相应锁强度。活动集合建议按实际路由逐项列举：用户主动课堂/学习读写可计，轮询、WS ping、失败请求、后台重连及 token 轮换不计；成功判定与 touch 的提交边界必须一致。使用较早的 idle/absolute 截止，等于即过期。
- **替代与取舍：**当前优先不引入独立异步 touch，以减少跨事务撤销空窗；若热点锁实测要求节流/分离，另交条件更新与业务授权一致性证明。不能先共享后升级造成互等，也不能为性能放宽 user 锁或把 last_seen 当近期认证。
- **S1 需审定：**活动分类原则、保守不节流的首轮方案及需要复验的并发负载。既定学生 14/30 天、管理员 15 分钟/8 小时及 remember_me 语义不重新选择；完整重登才建立新绝对期。
- **S2 细化：**逐路由映射、touch 字段/事务/锁集、双刷新与撤销竞争、token/CSRF 轮换及丢响应处理；不能把预检查 Boolean 跨连接传作最终授权。关联 **A08–A10、A16、A19、A25**。

### T06 — Origin、CSRF 与代理：浏览器默认精确同源

- **推荐与依据：**浏览器认证写入及 WS upgrade 采用精确 scheme/host/port allowlist，独立校验 CSRF、内容类型及大小；缺失、`null`、异常 Origin 默认拒绝。应用配置固定可信代理身份/跳数，只从该边界接收转发来源与外部 scheme/host；不得直接相信任意 X-Forwarded-*。
- **替代与取舍：**非浏览器或本机专用命令使用独立、受审的控制协议，不为兼容 CLI 全局豁免 Origin。开发合成证书/域名独立配置，不使用通配带凭据 CORS 或模糊域名后缀判断。
- **S1 需审定：**本地 HTTPS/WS 拓扑、直连与经受信代理两组环境、默认拒绝缺失 Origin 的预期；若客户端存在必要例外，列具体客户端和独立证明后另审。
- **S2/启用前细化：**合法 origin、代理配置来源/变更批准、Host/转发头校验、Cookie/CSRF、错误响应与客户端行为。真实域名和部署代理在启用前确定，不要求现在购买/配置。关联 **A06–A08、A20–A23**。

### T07 — 四类时间与协议 TTL：将 R01 写成两个独立谓词

- **推荐与依据：**吸收复审 P3 表达建议 R01：验证阶段要求 `verified_at < challenge_expiry`；执行阶段在取得全部锁后检查实际 DB 时间 `< operation_deadline`，且当前资格/pending/flow 有效。不能在已验证的证明执行阶段重新要求其旧 challenge 尚未到期，也不能重置 verified_at。
- **候选与取舍：**保留既有独立 challenge 5 分钟、pending 10 分钟、邮件 reset 15 分钟、WS ticket 30 秒及 upgrade 首帧 5 秒作为实验候选。issue/complete 各自单次且至多 120 秒是既定边界；五分钟/十分钟绝不延长它。WS ticket 与首帧是独立 deadline，任一先到均拒绝。
- **S1 需审定：**候选 TTL 的实验输入及边界组，包括 4 分钟延迟、challenge 4:59/5:00、最后一把锁跨 120 秒、已消费 issue 的有效 pending 上 fresh complete、旧 complete 重放。preauth 建议独立 TTL 5 分钟、每匿名上下文同时 1 份活跃记录、部署最多 200 份活跃记录；创建准入建议同来源 90 次/分钟、部署总计 120 次/分钟，均为本次待审资源建议。同来源值为正常校园 NAT 合成组每分钟 60 次完整登录各新建 preauth 另留 50% 余量；不能把创建预算误当密码失败预算或以客户端伪造来源绕过。到期清理不延长已有证明，重建上下文不清账号/跨入口预算；须测校园 NAT 正常组与分布式耗尽，缺存储/总量满时有界拒绝，不授业务权。其 TTL 恰好相同也不能复用 login/运维 challenge 对象或授权。
- **S2 细化：**四时间分别持久表示、单次 nonce/action/参数绑定、DB clock 使用、时钟回拨/异常拒绝与响应；不要求独立恢复执行者取得丢失的 Web MFA。关联 **A16、A21、A33、A36、A41–A44**。

### T08 — TOTP、KEK 与恢复码候选

- **推荐与依据：**成熟 TOTP 组件，既有 30 秒/±1 时间步候选仅作实验输入；锁内推进同凭据已消费时间步，跨 login/reauth/recovery 至多一次。新因子 pending 确认前保留旧因子；seed 由版本化 KEK 加密，仅受限验证内存路径解密，KEK 故障拒绝，不存明文或降级。
- **替代与取舍：**更窄接受窗口可比较漂移与失败率，但不能根据“更方便”放大到无界窗口；接受未来步后如何推进也必须实测。恢复码既有每组 10 个、每码至少 128-bit 熵作为待审候选/下限，随机源与用途分域摘要应明确，不以普通 hash 处理低熵密码。
- **S1 需审定：**窗口和漂移/回拨/并发用例、KEK 隔离与故障注入方案；普通新设 MFA、恢复码自动重绑与 manual final 分开，不能沿用一个响应覆盖全部路径。
- **S2/启用前细化：**因子版本/状态、时间步消费 SQL、KEK 接口/权限/轮换及错误；真实 KEK/保管设施待启用前按受审流程建立，本轮仅合成材料。关联 **A11–A13、A17、A24–A26、A35、A36、A46**。

### T09 — 多维限流与部署级资源预算

- **推荐与依据：**Alpha 首轮优先复用真实 PG 的短事务原子预算作为合成方案，覆盖账号、来源/NAT、challenge、跨入口和全局昂贵计算。准入短事务提交释放后再进入身份事务，不能持预算锁等待 user/session。设置部署级有界 hash 执行槽、队列长度和等待期限，进程增加/重启不能扩大总预算。
- **替代与取舍：**独立共享限流存储可减少 PG 热点，但增加一致性、运维和故障语义，当前先不新增；PG 原子计数也不能持锁 sleep。账号键采用服务端规范化输入与受保护摘要，未知账号走等价预算/dummy，日志不落密码或可枚举账号资料。限流存储不可用时拒绝新增昂贵认证，不默认为无限制。
- **S1 需审定：**既有账号失败 5 次/15 分钟、30 秒起渐进延迟/15 分钟候选封顶，IP 20 次失败/分钟，challenge 5 次及账号跨 challenge 10 次/30 分钟、邮件 3 次/小时和 60 秒重发等只作候选；须测校园 NAT、跨入口、多进程、攻击者诱导锁号。这里 IP 数值仅指密码验证失败计数，不把成功登录计入该失败预算；preauth 创建预算和昂贵计算总准入另算，不能合并三个计数口径。匿名失败不得永久冻结管理员。2 vCPU 服务预算的首轮新增建议是全进程合计 2 个 hash 槽、8 个等待位、排队最多 1 秒；队列满拒绝 p99≤500ms，不做昂贵计算。槽位必须跨进程共同受限，取消/断连不能在实际 hash 尚运行时提前释放并扩大同时在算量；具体租约、存活证明和回收协议留 S2。
- **S2 细化：**计数维度/窗口/键保留、原子 SQL、预算角色 ACL、租约/崩溃回收、队列满错误、跨入口重试、资源及账号隐私。未知账号也受相同预算，不为性能跳 dummy。关联 **A03、A04、A06、A11、A14、A18、A27、A30**。

### T10 — Argon2id：先比较再冻结，预算由实测资源推导

- **推荐与依据：**使用现有成熟 Argon2id 组件，64 MiB/t3/p1 为首要比较候选，保留既有 H-A–H-F 六组；旧合法 PHC 验证与新设角色政策分开。实验按真实全进程 RSS/CPU、执行槽及队列峰值推导部署级预算，`m` 不再次机械乘 `p`；ASGI event loop 不直接运行 CPU hash。
- **负载与取舍：**本次待审正常混合负载建议 **30 个合成用户、30 条 WS、10 business requests/s、1 login/s**；hash 筛选并发 1/2/4/8，突发 16/32，过载 10 分钟，内存余量 25%。这些均为实验输入/目标候选，不代表 30 人总会同时登录或已选机器，具体流量及指标见[实验环境](EXPERIMENT-ENVIRONMENT.md)与[验收](ACCEPTANCE-AND-EVIDENCE.md)。低成本组只作对照，未达阈值时提交资源/容量/体验取舍，不自动降低成本。
- **S1 需审定：**环境与采样方法、候选 p95/p99/正常业务退化/内存指标及总进程预算；开发机筛选不能代拟部署复测。PHC 异常参数上限、失败/取消/断连和 rehash 故障用例不能省。
- **S2 细化：**组件版本、PHC 允许参数、受限 verify/needs_rehash、比较原 hash/epoch 的条件写回；并发 reset/disable 已提交后禁止迟到 rehash 写回旧密码或签旧证明。建议 rehash 写入故障安全失败本次登录，保持旧合法 hash，不覆盖并发变更；该可用性选择待审。关联 **A01、A03、A04、A14、A25、A27、A30**。

### T11 — status：同事务 op 事实、当前原执行者授权与保留边界

- **推荐与依据：**最小 case/op 事实与 final 的 nonce/cap 消费、因子/epoch 变更和审计同事务提交；查询由当前合格的原稳定 actor/authority 按 stored_executor_type/id 过滤。status 独立只读证明绑定 case/op、用途和至多 2 分钟期限，不消费恢复写 nonce/cap；cap 已消费或 target 升 epoch 不影响此重新认证路径，执行者撤权仍拒绝。
- **事实与取舍：**committed 需同事务持久提交事实；not_committed 仅在受限共享锁和读取线性化点能够证明指定 op 未提交且 pending 有效时返回；查不到、已清理、故障或证据不足一律 unknown。普通只读副本的可能延迟不能用于推断 not_committed。not_committed 也不授重做权，后续须 fresh 单次写证明、锁内重读当前 case/op，completed 拒重签/再切因子。
- **S1 需审定：**建议终态最小 op/audit 事实保留 **90 天**，此为本次新待审建议；未决记录不得因到期被推断失败，清理后 status 只能 unknown。实际期限须核对隐私/删除承诺，不能为可用性无限保存核验材料。D0 高水位/撤销控制墓碑与这类可清理查询记录分开，不能按 90 天把反回滚状态降回旧值。
- **S2 细化：**op ID/执行主体不可变绑定、事实唯一性、锁/隔离级别、返回前资格/期限重核、并发提交/清理、摘要及保留清理 ACL；只投影必要阶段/提交事实/非秘密 op/audit。重复查询零恢复业务写，不重签、不 final、不回码；浏览器旧 cap 无此 status 权限。关联 **A25、A34–A36、A43、A44**。

### T12 — N01：独立 identity 事件，完整生产/领取/投递锁图

- **推荐与依据：**保留复审认可的独立 identity 内部事件/提交通知，不竞争业务 owner counter/Outbox，不新增公开 WS 事件。安全事务按 user/authority/case 等既定序后追加最小审计与内部记录；现有仅支持 account_activated 的 identity_events 不被假称可直接支持重复撤销。
- **替代与取舍：**优先评估最小独立内部撤销记录，以免改变旧激活事件的唯一语义；若最小增量复用旧表更合适，须单独提交兼容差异。通知只加速关闭，PG 实时撤销是正确性依据，通知丢失不能放行旧权限。
- **S1 需审定：**接受“禁止共享业务 counter/Outbox”及 producer→claim→delivery 分事务原则；领取只锁 event 并提交释放，随后另事务检查当前授权/关闭连接，不能持 event 等 user/counter。
- **S2 细化：**完整显式锁与 FK/UNIQUE/trigger 隐式锁、重试/清理/投递全路径和 ACL；以旧 counter 已存在、LocalReconciler 持 counter 后由 Outbox FK 等 user 的双连接 barrier 证明新安全事务不再反等 counter。不能笼统降 user 锁强度；数据库有界重试不重复外部 Provider。关联 **A19、A25、A28、A45**。

### T13 — N02：final 无新码，完整重登后显式生成

- **推荐与依据：**manual final 仅废弃旧恢复码组，不生成或交付新码。完整密码＋新 MFA 登录后，以所需近期证明显式生成/轮换新组；no-store、只展示一次、仅持久摘要。提示“尚未生成新组”不阻止已完成新 MFA 的完整登录。
- **替代与取舍：**不另建 final 期间跨 epoch 的秘密领取能力，不复用 confirmMfa→RecoveryCodes 作为 manual final 响应；CLI、status、旧 cap 都不能领码。这一较小协议已被设计复审接受，不重新选择相反方案。
- **S1 需审定：**独立生成/轮换的操作边界和丢响应用例；SECRET_ALREADY_ISSUED 只说明不回放旧秘密，不能自动重签或隐藏生成新组。
- **S2 细化：**正式生成接口/状态/错误、近期证明等级及具体操作绑定、客户端一次展示/复制提示、丢响应后重新认证显式整组轮换及旧组撤销原子性；不知道结果先读非秘密事实。关联 **A12、A24、A35、A36、A46**。

### T14 — 秘密输入/交付：受限本机通道与绑定 TLS 浏览器

- **推荐与依据：**CLI argv 只带 case/op 等非秘密定位符；秘密用不回显 prompt、受限 FD 或本机认证通道，响应只到批准计划绑定的 TLS 接收浏览器且 no-store。临时接收端公钥/随机挑战指纹经独立渠道核对，纳入签名计划；更换接收端须 fresh 批准与 flow generation 原子废旧。
- **替代与取舍：**不以 env、argv、URL、剪贴板脚本、stdout/stderr 或单一邮箱控制交付 cap/seed/私钥。FD 并非天然安全，必须实测 ACL/继承/关闭；硬件接口可评估但不要求采购，不自制签名密码学。
- **S1 需审定：**各合成平台输入/交付路径及异常、取消、trace、终端录制、APM、core dump 的故障用例。持久证据只记合成秘密标记存在/缺失断言，不录秘密原文。
- **S2/启用前细化：**prompt/FD/peer API、禁止录制/诊断转储的实际控制、浏览器接收端 PoP、响应丢失与重签协议、日志清理边界。PG/KEK/必需审计失败全回滚，秘密不进 Receipt/Outbox；不能靠“约定不打印”验收。关联 **A17、A24–A26、A33–A37、A46**。

### T15 — 学生核验证据：两类独立预登记依据、最小留存

- **推荐与依据：**原邀请/注册主体映射加独立核实在籍身份，并结合预登记独立联系渠道的现场挑战；仅邮箱、邀请码、昵称、截图、浏览器 session 或课堂知识不足。建议优先学校正式目录独立回联或当面核对，留来源/方法/版本与结论引用，不复制证件影像、不收密码/seed/恢复码或课堂正文。
- **替代与取舍：**可接受证据组合要由技术审查明确，无法形成可靠绑定时 case 保持未核实，允许补材料/复核而不降低核验。不以管理员勾选“已核实”代替独立来源，也不因便利性赋予全部 Admin 专用恢复权；核验/批准/执行可由同一已获权人承担但分别留痕，不新增强制双人政策。
- **S1 需审定：**合成证据模板、独立性判断与不足/冲突用例。建议核验详情引用在终态后 **30 天**清理，保留更小的“核验方法/结论/执行标识”审计按 T11 另审；此为新待审最小化建议，不表示已取得学校目录访问权或获得真实学生资料。
- **S2/启用前细化：**来源访问授权、可信渠道预登记/更新、证据不可替换摘要、获权 Admin 映射、留存与删除/申诉规则；若需要新增资料收集或改变既定隐私承诺，先单独交用户决定。真实执行者及来源登记留真实启用前完成，本轮仅合成模板。关联 **A18、A31、A33、A34、A38**。
