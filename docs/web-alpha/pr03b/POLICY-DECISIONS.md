## 2. 已确认产品决定

### P01：条件性剩余风险接受及适用阶段

用户已确认：**保留学生最低 6 字符及 MFA 可选；在补偿措施验证通过后，仅对 10–30 人邀请制 Web Alpha 接受已说明的剩余风险。** 接受决定已经作出，生效条件尚未满足。不能把文档完成或本地提交当作补偿验证通过，不能把该接受扩大到公开注册、更多用户或其他阶段，也不据此授权真实用户开放、部署或收费。

剩余风险包括在线和数据库泄露后的离线猜测、凭据填充、被盗会话、实时钓鱼及恢复滥用。邀请制和规模小不消除风险；在线限流无法阻止离线猜测，Argon2id 不使短密码等同长密码，TOTP 不等于抗钓鱼认证。

接受生效所依赖的补偿措施须有真实机制证据：本地常见/泄露密码阻断、多维/跨入口原子限流、未知账号等价计算与通用错误、异常告警和撤销、学生 MFA 与恢复码提示、HTTPS/Cookie/CSRF、经目标环境验证的 Argon2id 成本和秘密隔离。具体证据、参数、环境和剩余风险由 Astra 独立审查；未通过则保持开放门禁关闭，不由实现者降低要求。

接受记录须关联本次产品决定、批准人/日期、版本、环境、人数范围及补偿证据。扩大规模/公开注册、确认账号接管或泄露、部署资源或哈希成本变化、恢复执行身份变化及异常指标变化时重新复审；本次接受不覆盖未来变更。

### P02：管理员密码

**已确认产品：最低12字符，不强制字符组合，管理员MFA强制；建议实际使用密码管理器生成16字符以上密码。** 常见/泄露密码筛查适用于注册、新设/修改/重置密码；管理员创建、修改、重置及恢复后的新密码执行同一管理员门槛。16字符以上为使用建议，不变成另一个最低长度要求。

角色必须由服务端可信账号/token/session 确定，不允许请求方通过声明 Student 角色使用 6 字符管理员密码。验证已有凭据与设置新密码分开，不能把新设门槛误用为登录的静态拒绝条件。具体三模型、后端入口、字符计数、fixtures 和兼容更新仍待 Astra 契约审查。

### P03：管理员期限、Cookie 与 remember_me

**已确认产品：管理员会话空闲 15 分钟、绝对 8 小时，使用非持久 Cookie。** `remember_me` 不为管理员创建持久 Cookie，不延长期限、不减少 MFA 要求。实际请求真假值的处理、产品反馈和契约描述需一致审查，不能在实现中静默变成更长会话。

**学生 `remember_me` 只影响 Cookie 持久性：** `true` 为持久 Cookie，`false` 为浏览器会话 Cookie；两者服务端均执行空闲 14 天/绝对 30 天。持久 Cookie 到期不得超过服务器绝对剩余期限。浏览器可能恢复会话 Cookie，关闭窗口不等于服务器注销；主动退出必须撤销服务端会话。

轮换会话标识、敏感再认证及合法活动不延长原绝对期限；完整重新登录才建立新逻辑会话。显式业务活动、心跳/轮询/失败请求的区别及路由集合属于待 Astra 审查的技术定义，验证不能重新选择另一组管理员产品期限。

### P04：分级再认证及高风险单次操作绑定

以下期限和方向为**已确认产品**。窗口从服务器记录的实际因子成功验证时间起算，不能使用前端时间、最后活动时间或票据签发时间。

| 等级 | 已确认代表操作（其他路由归类待审） | 已确认窗口及因子 |
|---|---|---|
| R0 | 普通学习、本人会话列表；已有非敏感管理只读 | 有效会话；任何运营接口仍需 Admin＋已完成 MFA，不给本人会话列表追加普通敏感操作门槛 |
| R1 | 撤销其他设备/会话等 | 学生10分钟、管理员5分钟；当前密码＋已启用的现有MFA |
| R2 | 改密码/邮箱等 | 5分钟；当前密码＋已有MFA；新因子另外确认 |
| R3 | 注销账号、关闭/替换MFA等高风险操作 | 2分钟；学生按其MFA状态验证，管理员必须密码＋MFA；**绑定具体操作、单次使用**，不能在窗口内泛用或重复执行 |
| 独立恢复 | 全部 MFA 因子/恢复码丢失 | 不使用普通再认证窗口作降级；按 P05–P07 的受控恢复方向 |

当前会话退出不被额外再认证阻挡。未启用MFA的学生不会因注销而被强制先启用MFA。全部退出、设备信任、启用MFA、恢复码轮换及既有管理账号状态/配额/邀请/开关写入的具体分级沿旧草案提交Astra路由映射审查，不将所有旧示例升格为本轮逐路由批准。本表不新增管理员运营、角色调整或任意配置API。

逐笔证明与 user/session/device/epoch、具体目的/目标/参数的绑定方法、单次消费事务、传输字段和错误状态待 Astra 技术契约审查；**单次具体操作绑定本身不再是可选产品候选**。不得先私加字段、header 或 token 语义再补审查。

`ReauthRequest.mfa_code` 可选只表示 wire 结构允许省略；管理员和已启用 MFA 的学生仍必须验证所需第二因素。省略、空字符串或恢复码不能换取普通敏感操作的 MFA 证明；恢复码只进入受限恢复流程。

### P05：学生人工恢复

**已确认产品：学生获得管理员人工恢复支持，使用 Admin 专用受控恢复命令。** 旧版“不提供人工清除 MFA”备选已被本次决定取代，不重新投票。具体核验协议、职责与命令权限仍待 Astra 审查，获授权管理员的实际执行身份仍待登记，当前没有可执行的正式恢复实现。

| 情形 | 产品及冻结边界 | 待完成的技术审查和登记 |
|---|---|---|
| 仅忘记密码 | 单次邮件重置；不清 MFA、不自动登录；增加既有 `security_epoch` 并撤销旧授权后重新登录 | 用途/期限/代次、并发消费、邮件捕获与撤销原子性 |
| 密码＋恢复码可用、TOTP 丢失 | 原子消费一个码，只取得受限新因子重绑能力；新因子确认前保留旧因子；完成后全撤销并完整登录 | 恢复状态/协议、期限、码组轮换、秘密响应丢失与审计 |
| TOTP 与恢复码全失 | 管理员核实学生身份，通过专用命令执行受控人工恢复；不能只凭邮箱或邀请记录清除 MFA | 获授权管理员身份及权限登记；核验证据、批准记录、受限重绑、旧授权撤销、故障原子性和申诉流程 |

专用命令须覆盖身份核验、权限检查、最小审计、受限重绑、旧授权撤销和故障原子性。数据库变更只由命令内部受审事务执行，**不允许操作员手工 SQL、改表或直接删除 MFA 记录**。核验材料不得包含密码、seed、恢复码或课堂正文；可用证据类型、最小留存和登记引用由 Astra 审查。拥有普通 Admin 角色不等于已登记并获得该命令的执行权限。

### P06：管理员人工恢复的唯一执行人

**已确认产品：管理员人工恢复仅由本次对话的项目用户本人，在验证其独立运维身份后，手动执行专用受控恢复命令；其他 Admin 无权执行。** “本人”是项目用户这个实际的人，不能解释为待恢复账号本人、任意声称“我是本人”的申请者或当前任意 Admin。不能把普通 Web Admin 会话、邮箱控制、知道项目资料或数据库访问权当作此独立运维身份的充分证明。

项目用户的独立运维身份及可信核验凭据尚待真实登记；具体身份注册、验证、凭据保管/失效、命令交付和权限方案见 [会话恢复设计](SESSION-RECOVERY-DESIGN.md)，均待 Astra 技术审查。本表不预先认定某个操作系统用户名、公钥或账号就是获授权的实际项目用户，也不请求在聊天中提供秘密。

有密码和有效恢复码的普通受限重绑路径依然不授运营权限。需要人工恢复时，仅上述项目用户可执行专用命令；命令覆盖申请人与目标身份核验、执行者独立权限、批准/执行审计、单次受限重绑、旧授权撤销和事务故障原子性。数据库更新由命令内部受审事务执行，禁止人工 SQL/改表。其他 Admin 不能通过恢复接口、工具 membership、转交 token 或“代执行”取得该能力。

恢复完成后必须确认新因子、废弃旧因子及旧恢复码、增加既有 `security_epoch`、撤销旧会话/派生授权，再通过密码＋新 MFA 完整登录恢复运营权限；不能通过恢复码或人工命令直接签发普通后台权限。匿名申请不能冻结目标管理员；只有有效恢复证明、核实身份或确认安全事件后才能按受审流程采取写入限制。

### P07：唯一管理员失去全部恢复因子

唯一管理员场景沿用 P06：**由项目用户本人经独立运维身份验证后，手动运行专用恢复命令**。不能要求先登录已失去因子的 Web Admin 账号，也不能为了可用性设置网页 bootstrap、隐藏超级账号、`skip_mfa` 或数据库手改入口。

必须在启用前完成项目用户独立运维身份及恢复核验证据的登记，并审查与该 Web Admin 因子独立的验证和受控执行方案。登记、审查或机制演练尚未完成时，工具不启用、管理写入不被临时放行；这是实现就绪门禁，不撤销已确认的人工恢复支持，也不把“找另一名 Admin 代执行”重新列为备选。

专用命令不得把密码、seed、恢复码、Cookie 或恢复 token 放入 CLI 参数、终端历史、日志或 APM；秘密的安全输入、一次展示和错误脱敏方式需审查。命令有秘密响应时同样遵循不回放旧明文、只存最小状态/引用的边界。本轮不创建实际恢复凭据、不执行真实命令、不读取真实身份秘密。

### P08：remember_me 的追踪入口

P08 编号保留供其他文档追踪，当前已确认内容统一见 P03：学生只改变 Cookie 持久性、服务端仍为 14 天/30 天；管理员非持久 Cookie、15 分钟/8 小时且强制 MFA。现有 [OpenAPI](../architecture/contracts/openapi.json) `LoginRequest.remember_me` 为必填布尔值，真假语义及客户端反馈须在正式契约审查中对齐，不再保留“管理员持久 Cookie”产品备选。

### P09：本地名单无效时的明确行为

**已确认产品：常见/泄露密码使用本地名单；没有有效名单时暂停注册、改密及密码重置，不影响正常登录。** 密码明文不得发给外部筛查服务，不引入在线查询备选。更新失败但仍有有效的已批准版本时可继续使用该版本；什么构成有效版本、陈旧期限、完整性验证及原子更新方法待 Astra 技术审查。

暂停范围为注册和新密码设置入口，包括管理员受控流程中的新密码设置；不能借恢复命令绕过。正常登录继续验证已有密码和所需 MFA，不因名单不可用而锁号、撤销正常会话或要求重设密码。名单不可用的响应、恢复可用性和重试行为须在正式契约与测试中一致说明。

限流仍覆盖账号、来源、challenge、跨入口与全局资源预算，并处理校园 NAT；匿名失败不得永久冻结管理员。PG、KEK 或审计故障时不自动降低哈希成本、免 MFA 或留下部分安全变更；这些机制尚未实验。

## 5. 不变的安全边界与停止点

恢复上下文不读课堂、正文、导出或管理员运营数据；恢复码和人工恢复命令都不能直接授普通后台权限。新因子确认前不删除旧因子。邮箱重置不清 MFA、不自动登录；匿名恢复申请不能冻结目标管理员。Admin 无他人正文后门，普通 HTTP 不得借内部 OwnerContext 绕过会话。
