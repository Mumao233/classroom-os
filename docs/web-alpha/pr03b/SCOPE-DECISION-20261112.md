## 决定

用户于 2026-11-12 把 PR-03b 的开发交给 Claude Code 接手，并在同日明确同意按下列方案收窄验收范围（原话：“同意收窄”）。本决定取代 [交接文档](HANDOFF-20261112.md) 第 6、8 节中与之冲突的验收要求；其余内容不变。

| 项 | 原要求 | 现要求 |
|---|---|---|
| 核心包 | 整包（含人工恢复、维护、容量、统计）一次验收 | 登录与会话、MFA、改密与重置、CSRF、WSS 票据、F01/F02 先收口。标准：VMware 来宾内全套回归通过，加一轮 Astra 独立复审 |
| 人工恢复与维护 M0–M4 | 随整包验收 | 代码保留，能力保持关闭，另列后续包验收；不作为核心包的阻塞项 |
| R05 账号枚举 | 108 分层、每组 1000 下限、自然等待 900 秒的完整 campaign（至少 864000 个序列） | 改为设计论证加小样本计时测试；测试配置可缩短预算窗口或注入时钟。完整统计 campaign 不再执行 |
| R02/R04 容量与准入 | 完整候选/长度/Unicode/冷热/worker 共存/长窗口/尾部置信矩阵 | 按 10–30 人 Alpha 目标配置的已有单点结果收口，不再补全矩阵 |

## 没有改变的事

- 运行时规则不变：密码失败预算 3 次/900 秒，MFA 失败预算 5 次/900 秒且登录与再认证共享，preauth 300 秒，哈希 64MiB/t3/p1，共享 2 执行 8 等待。收窄的是验收方法，不是产品行为。
- 所有相关测试仍只在 VMware 来宾内执行，见 `J:\class-assistant\AGENTS.md`。
- 真实 D0、身份映射、核验与留存登记仍是对应真实能力的启用条件。
- 提交需要授权；不自动推送、合并、部署。

## 如实保留的限制

- R05 收窄后的结论是“设计上不区分已知与未知账号，小样本计时未见可区分差异”，**不是**原统计标准（BA/AUC 上界 0.55）下的通过。原 campaign 记为“未执行”，不记为“通过”。
- R02/R04 依据的容量单点（run `02cf87c84f0f4d3fb1c6a6cdbd01621e`）是 2026-11-10 在已退役的 WSL 环境取得的历史结果，没有在 VMware 重跑；其 Linux namespace/cgroup 工具无法在当前 Windows 来宾内运行。它只支持该配置的点估计，不代表目标部署平台、worker 共存或尾部置信。
- 此前业务 p95 劣化 30.356% 与 22.708% 的失败记录、各轮独审结论和冻结包原样保留。
- 用户规模或暴露面超出邀请制 10–30 人 Alpha 时，应重新评估本决定。
